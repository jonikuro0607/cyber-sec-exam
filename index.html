課題Ⅰ｜情報セキュリティ総論

情報セキュリティの3要素＋4要素

  • 機密性＝許可された人だけが見られる（アクセス制御・暗号化）
  • 完全性＝改ざん・破壊されない（ハッシュ・電子署名）
  • 可用性＝必要なとき使える（冗長化・バックアップ・UPS）
  • 追加4要素：真正性（本人性）／責任追跡性（誰がやったか追える）／否認防止／信頼性

リスクマネジメント

  • リスクアセスメント＝特定 → 分析 → 評価、その後にリスク対応
  • リスク対応の4分類：低減（対策）／移転（保険・委託）／回避（やめる）／受容（受け入れる）
  • 分析手法：定量的（金額・確率で数値化）／定性的（大・中・小のレベル評価）

ISMS（情報セキュリティマネジメントシステム）

  • ISO/IEC 27001（JIS Q 27001）。PDCAで継続的改善。経営層の関与・ポリシー策定が前提。認証は更新審査が必要（取りっぱなし不可）。

主要な法令

  • 個人情報保護法：要配慮個人情報（人種・信条・病歴・犯罪歴等）は取得に原則同意。第三者提供も原則本人同意。
  • マイナンバー法：利用目的が社会保障・税・災害対策に限定。厳格な安全管理義務。
  • 不正アクセス禁止法：なりすましログイン・他人ID提供（助長行為）を禁止。
  • 不正競争防止法：営業秘密（秘密管理性・有用性・非公知性の3要件）を保護。
  • サイバーセキュリティ基本法：国の基本理念と国・自治体・事業者の責務を規定（NISC）。
  • 電子署名法：一定の電子署名に手書き署名・押印と同等の効力を付与。
課題Ⅱ｜脅威と情報セキュリティ対策

人的脅威・内部対策

  • ソーシャルエンジニアリング：人の隙を突く非技術的手口（なりすまし電話・肩越しの盗み見・トラッシング＝ゴミ箱あさり）。
  • 内部不正対策：最小権限の原則・職務分掌・退職時の権限削除・ログ監視・教育。

物理・運用

  • 入退室管理（アンチパスバック＝入退記録の整合、共連れ防止）／クリアデスク・クリアスクリーン（離席時の片付け・画面ロック）／UPS（停電時の一時給電）。
  • 情報資産は台帳で洗い出し、重要度で分類・責任者設定。紙・人・設備も資産。

モバイル・テレワーク

  • BYOD（私物端末の業務利用）：ルール策定＋MDM（遠隔ロック・データ消去）が必須。

事業継続・バックアップ

  • BCP：有事に重要業務を継続/早期復旧。RTO＝復旧目標時間、RPO＝どの時点まで戻すか（許容データ損失）。
  • バックアップは3-2-1ルール（3コピー・2媒体・1つは遠隔/オフライン）。ランサム対策に隔離保管。
  • 冗長化用語：フォールトトレラント（故障しても継続）／フェイルセーフ（安全側へ）／フールプルーフ（誤操作対策）。
課題Ⅲ-A｜認証と暗号の基礎

認証

  • 3要素：知識（パスワード）・所持（トークン/スマホ）・生体（指紋/顔）。種類の違う2つ以上＝多要素認証(MFA)。
  • 生体認証：FRR（本人拒否率）とFAR（他人受入率）はトレードオフ。
  • SSO：一度の認証で複数サービス（MFA併用が望ましい）。FIDO/パスキー：公開鍵方式のパスワードレス認証でフィッシングに強い。

暗号

  • 共通鍵暗号（AES）：同じ鍵で高速。相手ごとに鍵が必要で鍵管理が課題（鍵配送問題）。
  • 公開鍵暗号（RSA）：公開鍵で暗号化 → 秘密鍵で復号。鍵配送問題を解決するが低速。
  • ハイブリッド暗号：本体は共通鍵、その鍵を公開鍵で配送（TLSで利用）。
  • ハッシュ：一方向で戻せない。改ざん検知・PW保存に。電子署名：完全性＋真正性＋否認防止。PKI/認証局(CA)：証明書で公開鍵の持ち主を保証。
  • HTTPS(TLS)：通信を暗号化＋サーバ証明書で接続先のなりすましを検知。
課題Ⅲ-B｜サイバー攻撃の種類と手法 ★2026 追加

マルウェア

  • ウイルス（寄生）／ワーム（自己増殖し単独拡散）／トロイの木馬（偽装）／ランサムウェア（暗号化＋身代金。近年は二重恐喝＝データ暴露も脅す）／スパイウェア（情報窃取）／ボット（C&Cサーバの指令で動く＝ボットネット）。

標的を狙う攻撃

  • 標的型攻撃（特定組織へ偽装メールで長期潜伏）／水飲み場型（よく見るサイトを改ざん）／ドライブバイダウンロード（閲覧だけで感染）／サプライチェーン攻撃（取引先・ソフト供給元を踏み台）／ゼロデイ（修正前の脆弱性を悪用）。

パスワード・なりすまし

  • ブルートフォース（総当たり）／辞書攻撃／パスワードリスト攻撃（漏えいID/PWの使い回しを悪用）／中間者攻撃(MITM)（通信に割り込み盗聴・改ざん）／フィッシング（偽サイト誘導）。

サービス妨害・ネットワーク

  • DoS/DDoS（過負荷で停止。DDoSは多数の踏み台から一斉）／DNSキャッシュポイズニング（偽の名前解決で偽サイトへ誘導）。

Webアプリ攻撃

  • SQLインジェクション（不正SQL）→プレースホルダ／XSS（閲覧者のブラウザでスクリプト実行）→出力エスケープ／CSRF（ログイン中の利用者に不正操作）→トークン検証／ディレクトリトラバーサル（パス操作で非公開ファイル閲覧）。
課題Ⅲ-C｜Webセキュリティとネットワーク防御 ★2026 追加
  • ファイアウォール：通信を許可/遮断（パケットフィルタ型・ステートフル型）。DMZ：公開サーバを内部LANから隔離する緩衝区画。
  • IDS＝検知・通知／IPS＝検知＋遮断／WAF＝Webアプリ層(SQLi・XSS等)の攻撃を防御。
  • VPN：公衆網上に暗号化トンネル。TLS：通信暗号化と相手認証。
  • 多層防御：境界・端末・データ・運用を重ねる。ゼロトラスト：社内外を問わずアクセスごとに検証（境界型からの転換）。
  • EDR（端末の不審挙動を検知・対応）／SIEM（ログ集約・相関分析）／SOC（監視運用組織）。
課題Ⅲ-D｜クラウド・モバイル・IoTのセキュリティ ★2026 追加

クラウド

  • 区分：SaaS（完成アプリ）／PaaS（開発・実行基盤）／IaaS（仮想サーバ等の基盤）。下層ほど利用者の管理・責任が広い。
  • 責任共有モデル：基盤は事業者、データ・権限・設定は利用者。漏えいの典型は設定ミス（公開状態の放置）。CASBでクラウド利用を可視化・制御。

API

  • APIキー/トークンで認証・認可、TLS暗号化、レート制限。キーのソース直書き・公開はNG（シークレット管理）。

モバイル・IoT

  • MDM（端末全体の管理）／MAM（業務アプリ単位の管理）。アプリ権限の確認も重要。
  • IoT：初期パスワードの変更・ファームウェア更新・不要機能の停止が必須（放置はボットネット化の温床）。
課題Ⅲ-E｜インシデント対応とフォレンジック ★2026 追加
  • 対応の流れ：検知・分析 → 封じ込め → 根絶 → 復旧 → 事後対応（教訓化）。
  • CSIRT：インシデント対応の専門チーム。社外はJPCERT/CC等と連携・届出。SOCは日常監視運用。
  • ログ管理：原因究明・追跡のため取得・保全（改ざん防止）。
  • デジタルフォレンジック：証拠の完全性を保ち、取扱い履歴（チェーン・オブ・カストディ）を記録。原本は保全し複製を解析。収集は揮発性の高いもの（メモリ・通信）から優先（RFC 3227）。

合格への学習のコツ

① まず「用語の正確な区別」を固める

この試験は「最も適切／最も不適切なものを選べ」形式が中心。似た用語（例：フォールトトレラント／フェイルセーフ／フォールトマスキング、共通鍵／公開鍵）を違いで覚えるのが得点源です。

② 法律は「何を禁止／義務づけているか」で押さえる

不正アクセス禁止法・個人情報保護法・不正競争防止法・サイバーセキュリティ基本法。条文暗記より「対象・行為・例外」を整理。

③ 2026追加のサイバー分野を厚めに

攻撃手法（ランサムウェア・標的型・サプライチェーン・ゼロデイ）と防御技術（WAF/IDS/IPS/多要素認証/暗号）はセットで。インシデント対応の流れ（検知→封じ込め→根絶→復旧→事後）も頻出。
